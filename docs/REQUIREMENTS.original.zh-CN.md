# BIT 校园网智能认证与连接管理器——完整功能需求清单（V1.0）

**目标：开发一款面向北京理工大学校园网的智能认证与连接管理软件，支持 Windows 桌面交互、开机无人值守认证、网络状态监测、自动故障恢复和安全凭据管理。**

本清单综合了你此前提出的全部要求，并参考 BitGateway 当前提供的用户功能，重新从产品需求出发进行整理。**功能范围不受 BitGateway 或 BIT-Connect 现有架构、编程语言和实现方式限制。**

## 一、产品定位与设计原则

### 1.1 产品定位

软件应同时满足两类使用场景：

**普通桌面用户：** 安装后通过 GUI 完成校园网登录、查看账户信息、配置自动登录，无需具备管理员权限。

**无人值守设备：** 安装并启用后台服务后，设备可以在没有用户登录 Windows 的情况下自动完成校园网认证，并在网络异常或认证失效时自主恢复。

此外，应支持笔记本电脑、台式机、服务器、虚拟机，以及通过路由器连接校园网的设备。

### 1.2 核心设计原则

| 原则 | 具体要求 |
|---|---|
| 易用性优先 | 尽量减少安装、配置和日常使用中的人工干预 |
| 可靠性保障 | 开机认证、断线重连、网络恢复和程序异常恢复是基础能力 |
| 双模式运行 | 桌面模式与后台模式可以独立运行，也可以协同工作 |
| 单一认证控制 | 避免 GUI、后台服务或多个实例重复发起认证 |
| 安全存储 | 用户密码必须加密存储，避免普通用户和程序直接读取 |
| 网络环境感知 | 根据当前网络环境决定是否需要认证 |
| 最小权限 | 正常使用无需管理员权限，仅系统级操作按需提权 |
| 可维护性 | 各功能模块相互独立，方便调试、扩展和升级 |
| 兼容性 | 优先保证 Windows 10、Windows 11 和 Windows Server 的正常运行 |
| 可恢复性 | 尽可能避免升级、重新安装和异常退出导致配置丢失 |

### 1.3 优先级定义

| 优先级 | 定义 |
|---|---|
| **P0** | 必须实现，缺少该功能则不能认为产品达到基本目标 |
| **P1** | 重要功能，建议正式版本提供 |
| **P2** | 增强功能，可以在后续版本实现 |
| **P3** | 暂不计划实施，保留扩展可能 |
| **待定** | 需求方向已经提出，但具体行为仍需确认 |

特别说明：**可靠性属于产品必须满足的质量要求**。其他属性按照你提供的排序：易用性 > 上游兼容性 > 可维护性 > 安全性 > 轻量化。

# 二、完整功能清单

## A. 校园网认证与账户管理

这是软件的基础功能，所有运行模式都需要支持。

| ID | 优先级 | 功能 | 详细要求 |
|---|---|---|---|
| AUTH-01 | P0 | 校园网登录 | 使用用户名和密码向校园网认证服务器发起登录 |
| AUTH-02 | P0 | 校园网注销 | 支持用户主动注销当前认证会话 |
| AUTH-03 | P0 | 查询认证状态 | 判断当前连接是否已通过校园网认证 |
| AUTH-04 | P0 | 自动登录 | 在符合条件的网络环境中自动执行认证 |
| AUTH-05 | P0 | 保存账户 | 安全保存认证所需的用户名和密码 |
| AUTH-06 | P0 | 修改账户 | 用户可以修改用户名或密码 |
| AUTH-07 | P0 | 登录结果验证 | 登录请求完成后，进一步确认真实认证状态 |
| AUTH-08 | P0 | 错误识别 | 区分密码错误、认证服务器不可达、请求超时等故障 |
| AUTH-09 | P0 | 防止重复认证 | 已认证时不重复提交登录请求 |
| AUTH-10 | P0 | 手动注销保护 | 用户主动注销后，自动登录不应立即重新连接 |
| AUTH-11 | P0 | 会话状态同步 | GUI 和后台服务显示一致的认证状态 |
| AUTH-12 | P1 | 强制重新认证 | 在用户确认后执行完整的重新认证流程 |
| AUTH-13 | P1 | 账户信息展示 | 查看当前认证 IP、已用流量、在线时长、账户余额等可获取的信息 |
| AUTH-14 | P1 | 多种认证错误提示 | 将网关错误转换成易理解的提示 |
| AUTH-15 | P1 | 自定义认证服务器 | 默认使用 `10.0.0.55`，允许高级用户修改 |
| AUTH-16 | P2 | 多账户配置 | 保存多组校园网账户，支持手动选择 |
| AUTH-17 | P2 | 账户自动选择 | 根据网络环境或用户设置选择认证账户 |
| AUTH-18 | P2 | 会话使用统计 | 展示认证历史、持续在线时间及重连次数 |

### 认证行为要求

自动登录应符合以下条件：

1. 自动认证功能已启用。
2. 当前网络被判断为适合校园网认证。
3. 已保存有效的认证凭据。
4. 当前尚未认证，或者存在明确需要重新认证的状态。
5. 用户未主动暂停自动认证。
6. 没有其他认证操作正在执行。

所有条件满足后，软件才应自动发起登录。

如果认证服务器明确返回密码错误或其他需要用户处理的问题，软件应停止针对同一凭据的高频自动重试，并提示用户。

| MODE-11 | P1 | 模式切换 | 用户可以在 GUI 中切换桌面模式和后台模式 |

### 双模式之间的行为规则

| 当前状态 | 预期行为 |
|---|---|
| 未安装后台组件 | GUI 自行负责认证和状态监测 |
| 后台组件已安装且运行 | 后台组件负责认证，GUI 负责管理和显示 |
| GUI 关闭 | 后台组件继续工作 |
| Windows 用户注销 | 后台组件继续工作 |
| Windows 启动但无人登录 | 后台组件自动执行认证 |
| 后台组件发生故障 | GUI 显示故障；后台管理机制尝试恢复 |
| 用户切换回普通模式 | 停止后台认证控制，交接给 GUI |
| GUI 与后台同时启动 | 避免重复认证和状态冲突 |
| 其他版本的客户端同时运行 | 尽可能检测冲突并提示用户，无法可靠协调时避免破坏性操作 |

**后台组件是否通过原生 Windows Service 实现，属于技术方案选择。功能需求仅要求它具备可靠的无人登录运行能力。**

不过，Windows Service Control Manager 仍是实现这些功能的优先候选。

## C. 网络状态监测与智能环境识别

你对网络环境的要求比较广泛，因此这一部分应该成为正式产品中的独立功能模块。

### C1. 网络环境识别

| ID | 优先级 | 功能 | 详细要求 |
|---|---|---|---|
| NET-01 | P0 | 网络连接检测 | 判断设备是否已经建立有效网络连接 |
| NET-02 | P0 | 网络变化检测 | 识别网络断开、恢复、切换等事件 |
| NET-03 | P0 | 校园网认证环境判断 | 判断当前网络是否可能需要校园网认证 |
| NET-04 | P0 | 网关可达性检测 | 判断校园网认证服务器是否可访问 |
| NET-05 | P0 | 非校园网保护 | 避免在明显无关的网络环境中发起认证 |
| NET-06 | P1 | SSID 识别 | 根据 Wi-Fi SSID 辅助识别当前网络 |
| NET-07 | P1 | 有线网络识别 | 支持没有 SSID 的以太网连接 |
| NET-08 | P1 | 网络接口识别 | 获取网卡、IP、默认网关等信息 |
| NET-09 | P1 | 多网卡支持 | 识别多个同时存在的网络接口 |
| NET-10 | P1 | 网络环境变化重新评估 | 网络条件发生变化时重新判断是否需要认证 |
| NET-11 | P1 | 自定义网络规则 | 用户可以指定需要自动认证或忽略的网络 |
| NET-12 | P1 | 已认证路由器识别 | 尽可能判断当前网络是否已通过上游路由器认证 |
| NET-13 | P1 | 网络恢复后快速检查 | 网络从离线恢复时及时重新判断认证状态 |
| NET-14 | P2 | 多认证环境配置 | 针对不同网关或网络环境保存不同配置 |
| NET-15 | P2 | 网络环境历史 | 记录曾经识别过的网络及诊断结果 |
| NET-16 | P2 | IPv6 状态检测 | 检查 IPv6 地址和网络可达性，供诊断使用 |

### C2. 网络检测维度

软件应将以下检测维度分开处理：

| 检测维度 | 检测目标 | 主要用途 |
|---|---|---|
| 物理连接 | 网卡和链路状态 | 判断网线、Wi-Fi 是否连接 |
| 本地网络 | IP 地址、网关、路由 | 判断是否具备基本网络通信条件 |
| 校园网环境 | SSID、网关、认证服务器等 | 判断当前网络是否可能需要认证 |
| 校园网认证 | 校园网认证服务器状态 | 判断账户是否已认证 |
| DNS | 域名解析 | 判断 DNS 是否正常 |
| 外网连接 | 可信外部 HTTP 目标 | 判断实际互联网是否可用 |
| IPv6 | IPv6 地址、路由、连通性 | 辅助判断 IPv6 网络状态 |

### C3. 网络环境分类

建议产品至少区分以下状态：

| 网络状态 | 自动认证策略 |
|---|---|
| 无网络连接 | 暂停认证，等待网络恢复 |
| 普通家庭网络 | 不执行校园网认证 |
| 直接连接校园网，尚未认证 | 自动登录 |
| 直接连接校园网，已经认证 | 保持在线监测 |
| 通过路由器连接，且上游已认证 | 保持现有状态，避免重复登录 |
| 通过路由器连接，但上游未认证 | 判断是否能够安全完成认证，再决定是否登录 |
| 多网卡连接不同网络 | 优先根据具体认证出口和路由判断 |
| VPN 已连接 | 避免错误选择 VPN 出口，并尽量不干扰 VPN |
| DNS 异常 | 记录 DNS 故障，不直接认定认证失效 |
| 校园网认证服务器不可达 | 进入受控重试，不盲目注销 |
| 网络环境无法确认 | 采用保守策略，允许用户手动覆盖 |

### 关于路由器场景的重要边界

你之前特别提到多个设备经路由器共享一个校园网账户的情况。

应明确区分：

**设备已经能够使用路由器认证后的校园网连接**，以及**设备需要代替路由器完成上游认证**。

前者必须支持。

后者是否可实现取决于认证网关绑定会话的方式、请求实际出口、网络地址转换和路由器配置。

因此，建议将“检测并利用已认证路由器”列为 P1，将“从路由器下游替上游认证”列为待验证的增强需求，不承诺适用于所有网络环境。

### 推荐的默认恢复策略

以下参数是初步建议，属于可调整的设计默认值，并非用户已经确认的硬性要求。

| 情况 | 推荐行为 |
|---|---|
| 程序启动 | 立即检测 |
| 网络连接恢复 | 立即重新评估网络环境 |
| 已确认认证失效 | 尽快执行首次登录 |
| 认证成功 | 返回正常监测 |
| 临时网络请求失败 | 按指数退避进行重试 |
| 连续重试失败 | 最大间隔限制为 5 分钟 |
| 网络环境变化 | 取消旧网络的无效重试，重新检测 |
| 密码明确错误 | 暂停该凭据的自动登录并通知用户 |
| 认证在线但外网不可达 | 诊断网络故障，不自动注销 |
| 用户主动注销 | 暂停自动登录，直到用户重新启用或按既定规则恢复 |
| 长时间网络断开 | 保留后台运行和监测能力 |
| 服务异常退出 | 由系统级监控机制恢复 |

### 指数退避建议

初始重试间隔可以采用：

| 失败次数 | 等待间隔 |
|---|---|
| 第 1 次 | 5 秒 |
| 第 2 次 | 10 秒 |
| 第 3 次 | 20 秒 |
| 第 4 次 | 40 秒 |
| 第 5 次 | 80 秒 |
| 第 6 次 | 160 秒 |
| 第 7 次及以后 | 最长 300 秒，可增加少量随机抖动 |

这里还需要强调一个重要区别：**最大等待间隔和最大重试次数是两个不同概念。**

你希望长期无人值守，因此我建议默认允许持续重试，但设置最大等待间隔，并对不同错误类型采用不同策略。

明确的密码错误可以暂停认证；临时网络故障则应继续进行低频检查。

## E. 凭据安全与权限管理

你的实际安全需求主要是防止普通用户和普通应用直接读取密码，以及防止密文文件被复制到其他计算机后直接解密。

不要求抵御具有完整管理员权限的攻击者。

| ID | 优先级 | 功能 | 详细要求 |
|---|---|---|---|
| SEC-01 | P0 | 加密保存密码 | 不得将密码作为明文持久化保存 |
| SEC-02 | P0 | 用户身份隔离 | 普通 Windows 用户不能直接解密其他身份保存的凭据 |
| SEC-03 | P0 | 防止离线复制解密 | 单独复制凭据文件到其他电脑不能直接获得密码 |
| SEC-04 | P0 | 自动解密 | 无人值守后台能够在无人工操作时使用已保存的凭据 |
| SEC-05 | P0 | 安全修改密码 | 用户可以通过 GUI 修改凭据 |
| SEC-06 | P0 | 文件权限控制 | 正确限制凭据及相关配置目录的访问权限 |
| SEC-07 | P0 | 敏感数据日志保护 | 不允许日志意外记录明文密码或完整认证密钥 |
| SEC-08 | P0 | 权限最小化 | 后台组件仅获取正常运行所需的权限 |
| SEC-09 | P0 | 凭据损坏处理 | 无法解密时给出提示并允许重新输入 |
| SEC-10 | P0 | 服务凭据独立保护 | 服务模式下的凭据不依赖某个交互式用户登录 |
| SEC-11 | P1 | 安全配置通道 | GUI 能够安全地向后台组件提交新的凭据 |
| SEC-12 | P1 | 权限校验 | 限制可以修改共享凭据的用户范围 |
| SEC-13 | P1 | 凭据迁移 | 从旧版明文配置迁移至加密存储 |
| SEC-14 | P1 | 升级保留凭据 | 软件正常更新后已有凭据保持可用 |
| SEC-15 | P1 | 普通用户修改密码 | 安装完成后，授权用户不必每次修改密码都申请管理员权限 |
| SEC-16 | P1 | 凭据重置 | 支持主动删除已保存的账户密码 |
| SEC-17 | P1 | 凭据显示控制 | 默认不展示已有明文密码，允许通过覆盖方式修改 |
| SEC-18 | P2 | 多用户共享授权 | 支持管理员指定哪些 Windows 用户可以修改共享凭据 |
| SEC-19 | P2 | 备份与恢复引导 | 支持迁移非敏感配置，凭据无法恢复时引导重新输入 |
| SEC-20 | P3 | TPM 密钥保护 | 当前不需要 |
| SEC-21 | P3 | 抵御管理员攻击 | 不作为当前安全目标 |

### 推荐的凭据保护原则

普通桌面模式可以使用当前用户范围的 Windows DPAPI。

后台模式优先评估专用服务身份的用户范围 DPAPI，避免额外创建和维护传统 Windows 本地用户。

此外：

- 不使用硬编码密钥作为主要保护机制。
- 不自行设计密码加密算法。
- 不要求用户每次开机手动解锁后台凭据。
- 不将密码永久保留在安装目录的明文配置文件中。
- 不在 GUI 与后台通信时返回不必要的明文密码。
- 不因为一次凭据读取失败就删除所有配置。

**正常升级和重新安装应尽可能保留凭据；Windows 重装、密钥实际丢失或更换计算机后，允许重新输入。**

如果未来要求跨机器恢复密码，则需要单独设计受用户控制的恢复密钥或其他恢复机制。

# 三、跨模块行为规范

功能清单还需要明确不同模块之间的协作规则，否则很容易出现各模块单独工作正常、整体运行却不稳定的情况。

## 3.1 统一运行状态

建议软件至少区分以下状态：

| 状态 | 含义 | 允许自动认证 |
|---|---|---|
| Initializing | 程序正在初始化 | 暂不执行 |
| NoNetwork | 无有效网络连接 | 否 |
| UnknownNetwork | 无法确认网络环境 | 按保守策略决定 |
| NonCampusNetwork | 非目标校园网 | 否 |
| Checking | 正在检测校园网认证状态 | 等待结果 |
| Offline | 已确认尚未认证 | 是 |
| LoggingIn | 正在认证 | 不允许重复发起 |
| Online | 校园网已认证 | 不需要 |
| NetworkDegraded | 认证可能正常，但网络连接异常 | 先诊断 |
| Retrying | 登录失败，等待下一次尝试 | 按退避策略 |
| AuthError | 凭据或认证出现需要处理的错误 | 根据错误类型决定 |
| Paused | 用户主动暂停自动认证 | 否 |
| Stopping | 程序正在停止 | 否 |

这里应将**网络状态、认证状态、运行状态**分别保存，避免把所有异常都简化为一个“离线”状态。

例如，认证已经成功但 DNS 故障时，GUI 可以同时展示：

`校园网：已认证；互联网：连接异常；原因：DNS 解析失败。`

这样既方便用户理解，也能避免错误的重新认证。

## 3.2 关键状态变化的预期行为

| 事件 | 预期处理 |
|---|---|
| Windows 开机 | 启动后台组件，等待网络就绪 |
| 网络首次可用 | 判断当前环境，必要时自动认证 |
| Windows 用户登录 | GUI 连接后台服务并显示状态 |
| Windows 用户注销 | 后台服务继续运行 |
| 电脑睡眠 | 暂停不必要的检测 |
| 电脑恢复 | 重新获取网卡及认证状态 |
| 从校园 Wi-Fi 切换至家庭 Wi-Fi | 停止校园网认证尝试 |
| 从家庭 Wi-Fi 切换至校园 Wi-Fi | 重新判断并自动认证 |
| 网线断开 | 等待连接恢复 |
| 网线重新连接 | 立即重新评估认证环境 |
| VPN 启用 | 避免错误地通过 VPN 发起校园网认证 |
| 校园网会话过期 | 自动重新登录 |
| 校园网服务器无响应 | 退避重试 |
| DNS 故障 | 记录并诊断，不盲目注销 |
| 账户密码错误 | 暂停对应凭据的重复认证并通知用户 |
| 用户手动注销 | 暂停自动认证 |
| GUI 关闭 | 根据模式决定是否仅退出 GUI |
| 后台服务崩溃 | 自动重新启动 |
| 软件更新 | 保护服务配置和凭据 |
| 用户卸载软件 | 停止后台组件，按选择处理数据 |

# 八、明确不纳入当前版本的功能

为避免开发范围无限扩大，我建议将以下内容列为当前非目标。

| 功能 | 原因 |

# 十一、最终目标总结

结合你此前的所有要求，这款软件可以定义为：

> **面向北京理工大学校园网的智能认证与连接管理器，提供完整的桌面交互与独立后台运行能力。软件可以在 Windows 启动后、用户尚未登录时自动完成校园网认证，并根据网络变化、认证状态和实际连通性执行安全的自动恢复。用户可以通过统一 GUI 管理账户、连接状态、后台服务和网络设置。软件使用系统原生安全机制保护凭据，支持长期无人值守运行，并尽可能减少管理员权限需求和日常维护成本。**

我认为应重点保证五个核心体验：

**第一，安装简单。** 普通用户可以直接安装和使用桌面模式，需要无人值守时通过 GUI 启用后台运行。

**第二，开机即联网。** Windows 启动后，无需用户登录，后台组件能够自动完成认证。

**第三，断网能恢复。** 网络变化、认证过期和临时网关故障可以自动处理，同时避免无意义的重复认证和注销。

**第四，日常无感知。** 用户不需要始终打开 GUI，也不需要频繁处理服务、密码和网络状态。

**第五，异常可诊断。** 遇到不能自动解决的问题时，软件能够准确说明原因、保留日志，并允许用户通过 GUI 恢复。

这份清单可以作为后续编写正式 PRD、技术架构设计和开发验收标准的基础。它独立于 BitGateway 和 BIT-Connect 的现有实现，也不预先要求必须使用 Rust、Python、Iced、Windows Service 或特定的加密库。

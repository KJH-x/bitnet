# BitNet 前端

BitNet 用同一个认证引擎服务图形、终端和命令行用户。GUI、TUI、CLI 和 Web 日志查看器分别启动并通过现有 IPC 请求数据。引擎负责认证状态、权限、凭据和日志持久化。终端按键、浏览器请求以及界面刷新均使用现有的命令和回复类型。

## 桌面工作区

侧栏提供「连接」「账户」「网络」「后台服务」和「软件设置」。连接区使用「状态」「详情」「统计」「诊断」四个子页。状态页显示认证账号、网关所见 IPv4、所用网卡的 IPv4 和健康摘要。IPv6 详情分别显示本机地址和站点所见的出口地址。点击互联网、DNS 或 IPv6 状态可查看检测时间和结果。Windows 同时显示所选网卡的 DNS 服务器和配置方式。添加账户需要先验证登录。「设为当前」会尝试用保存的账户登录，已有其他账户在线时先确认，成功后再保存选择。确认窗口会提示远程桌面可能中断。网络区在网卡名称旁显示 IP，网卡地址、DNS 与连接页共用显隐开关。打开网卡页右侧的「高级」开关可切换到认证环境和网络规则。侧栏仅在系统后台可连接时提供「连接到后台」，连上后显示绿色「后台运行中」。在「后台服务」可单独管理运行与开机启动，或停止系统服务并切换到个人模式。软件设置包含「常规」「连接检测」「网络信任」「日志」「更新」「导入与导出」。进入更新页会检查新版，安装弹窗重新核验签名与更新范围。设置可直接复制或导出至系统保存对话框选择的位置。诊断页显示重点发现，并可在浏览器打开本机 HTML 报告。

IPv6 检测由系统选择路由和源地址。域名仅返回非公网 IPv6 时跳过连接。公网 IPv6 回显或通过固定 IPv6 地址完成的 HTTPS 检测可确认连通性。默认直连项使用 Cloudflare 公布的 IPv6 DoH 地址发送固定测试查询。站点未回显地址时，详情保留本机地址并将出口地址显示为空。默认和自定义检测地址均可在「软件设置 → 连接检测」修改。

本机 IPv6 的教育网标注依据代表性地址前缀。CERNET 使用 `2001:250::/32` 和 `2001:251::/32`，CERNET2 使用 `2001:da8::/32` 和 `240c:c000::/20`，FITI 使用 `240a:a000::/20`。这些标注只描述地址所在的地址块。

分页根据剩余窗口高度计算行数，列表缩短后回到最后一个可用页。长表单通过编辑对话框或子页展开，诊断报告可复制，配置 JSON 使用独立的编辑区域。窗口最小尺寸为 840×600 逻辑像素。

短弹窗用于验证账户、确认断开等操作。自动认证需要选择网卡时进入网络区，完成确认后回到原页面。详细日志从「软件设置 → 日志」打开或停止本机 Web 查看器。诊断页提供最新健康探测的脱敏报告。IP 地址默认遮盖，可由用户临时显示。Windows 托盘菜单使用当前界面语言，双击图标切换窗口显示。

## 进程生命周期

| 入口 | 行为 |
| --- | --- |
| `bitnet-tui` 或 `bitctl tui` | 使用当前终端，提供状态、检测、保存账户登录、暂停和恢复，以及近期日志的筛选、分页和详情 |
| `bitctl web start` | 启动当前范围的日志服务并打开默认浏览器 |
| `bitctl web stop` | 停止当前范围的日志服务 |
| `bitnet-web --no-open` | 在终端输出本次会话的访问地址 |

TUI 连接现有引擎，也可以按 `s` 启动个人引擎。界面使用 Ratatui 和 Crossterm，状态变化、输入或调整大小时更新，退出时恢复终端。按 `Tab` 切换状态与日志，按 `/` 筛选日志，按 `Enter` 查看详情，按 `w` 按需打开 Web 查看器。状态、日志和错误消息中的 IP 地址默认遮盖，按 `p` 切换本次终端会话的地址显示。

Web 查看器监听 `127.0.0.1` 的临时端口。查看令牌用于读取记录，控制令牌用于协调启动和停止。页面资源打包在程序中。浏览器可停止服务，服务在十分钟没有用户操作后退出。页面先加载最近一批记录，保持在首页顶部时持续更新。较早的记录按需加载，筛选、复制和 JSON 导出基于当前加载的记录。设置中的「清除诊断日志」移除引擎的 JSONL 诊断文件，登录记录和运行统计仍由活动数据库保留。

## 绘制跟进

TinySkia 在滚动日志弹窗时会对每块局部更新区域重复绘制遮罩和卡片。原有分组的 1120×780 实验中，首帧软件绘制中位数为 154 ms。已将该问题登记为待跟进项，主线暂缓修改渲染后端。

实验分支 `experiment/iced-vello-cpu` 保留旧版滚动布局，使用 Iced PR #3306 的 Vello CPU 路径。相同 Windows x64 场景下，同期 TinySkia 路径首帧中位数为 168.15 ms，Vello CPU 路径为 16.85 ms。一次滚轮滚动可见画面由 2–3 次变化增至 11 次。结果涵盖该 PR 的增量重绘和 CPU 光栅化整条路径。[Iced Vello CPU PR](https://github.com/iced-rs/iced/pull/3306)

# 图形界面与命令行使用说明

BitNet 的图形界面是独立进程 `bitnet-gui`，使用 Iced 0.14 和 tiny-skia 软件渲染，不需要 WebView，也不包含 wgpu。关闭界面不会停止独立运行的认证引擎。GUI、CLI 共用运行时 SDK、命令模型和状态，不各自实现认证循环。

## 首次配置

1. 运行 `bitnet-gui.exe`。界面先读取本地引擎状态；当前用户引擎尚未运行时，通过 SDK 启动它。
2. 打开“账户管理”，输入校园网账户及密码，选择“安全保存账户”。已保存的密码只能替换，不会回显或导出。更换密码时须重新输入新密码。
3. 选择当前账户。需要自动认证时，勾选“启用校园网络自动认证”，保存该设置；默认关闭自动认证。
4. 在“连接状态”查看校园认证状态及网络健康。两者分别显示，互联网探测失败不会自动注销已有校园会话。确认当前网络确实适合校园认证后，明确选择“信任当前网络”，才允许在该环境自动发送认证材料；也可确认仅登录一次，不保存长期信任。
5. 需要在无人登录时联网，打开“后台服务”启用系统服务，并按安装程序提示授权；然后在共享服务中配置账户。系统服务的凭据与个人引擎凭据分别管理，不会静默复制。

默认“自动选择”模式会在已安装系统服务时连接共享服务；即使服务尚未运行，也不会另起个人引擎。服务页面显示实际连接范围。安装、停止、卸载、修复系统服务及安装更新通过统一维护接口执行，需要授权时由系统提出。

## 页面

| 页面 | 可用操作与显示 |
| --- | --- |
| 连接状态 | 认证状态、网络环境、账户、IP、流量、时长、余额、互联网/DNS/IPv6 健康；登录、确认注销、检查、暂停/恢复、确认重新认证；首次账户引导 |
| 账户管理 | 新增、选择、替换账户密码、确认删除；只显示密码是否存在，不显示其内容 |
| 网络与规则 | 多环境配置捕获、选择和确认删除；接口状态、地址、网关、SSID、实际认证接口；指定接口或恢复自动选择；按优先级管理接口/SSID/网关/账户匹配及忽略规则 |
| 偏好与设置 | 中英文、系统/浅色/深色主题、自动认证、个人登录启动、隐藏窗口、通知偏好、检查间隔、退避上限、超时、保留天数、健康探测地址；不含密码的设置导入导出 |
| 后台服务 | 已安装、运行、开机启动状态和实际范围；经统一维护接口安装、启动、停止、卸载保留数据、修复；个人引擎可单独停止 |
| 日志与历史 | 读取引擎保留的脱敏事件，按类型或消息筛选，手动刷新最近 200 项，按需展开事件级别、重试和环境详情 |
| 运行统计 | 认证成功/失败、重连、事件数量、最近成功、平均恢复时间、观测在线总时长/最长在线段、中断与健康异常、当前会话流量和时长；观测时长不等于校方计费时间 |
| 网络诊断 | 按需调用引擎生成脱敏 JSON，查看和复制报告；该操作不会重置网卡或修改 DNS |
| 软件更新 | 客户端/引擎/API 版本；检查更新、确认安装已验证更新及更新偏好；服务更新仍逐次请求管理员确认 |

服务端能力、发布配置或安装包不满足某项操作时，界面显示 SDK 返回的错误；按钮存在不表示安装维护或跨平台操作已通过实机验证。

## 个人登录启动与系统服务

“登录后启动后台引擎”和“登录后启动 GUI”是两个独立选项。前者适合只需要后台运行、希望节省界面常驻内存的用户。系统服务则用于开机无人值守，与用户登录启动不同。

在默认“自动选择”模式下，即使实际连接共享服务，SDK 也会将这两个开关与当前用户的个人偏好叠加显示；保存时由 SDK 分开处理个人启动项，避免系统服务修改其他用户的登录环境。显式选择“系统后台”时直接管理服务范围，个人启动项应回到“自动选择”模式修改。

Windows 和 macOS 构建包含托盘菜单，可打开界面、检查、暂停、恢复或退出界面。点击窗口关闭按钮会隐藏界面；托盘“退出界面”只退出 GUI。Linux 构建不引入 GTK/AppIndicator 依赖，目前使用普通窗口，关闭后退出 GUI，独立引擎继续运行。没有可用托盘时不会让隐藏启动产生无法访问的窗口。

## 并发、确认与错误

GUI 每 2 秒读取一次本地状态快照；托盘事件单独处理。状态轮询不直接访问校园网关。历史、统计与诊断按页面或按钮调用统一命令。

设置从开始编辑时的 revision 提交。其他用户、CLI 或系统事件修改设置后，旧 revision 的写入会被引擎拒绝；用户可刷新并放弃草稿后重新编辑。状态回包不会覆盖未保存草稿；保存期间继续编辑的内容也不会被先前保存的回包静默清除。

网络信任由引擎记录接口、SSID、网关、来源 IPv4 网段及认证目标的指纹。未知网络可以查询状态，但不会自动发送账户凭据；设置导入不能增加信任。指纹用于限制自动认证范围，不能提供服务器身份的密码学保证；HTTP 校园门户仍可能被仿冒，不应把“已信任”理解成证书验证。取消当前网络信任会停止后续自动认证资格，不主动注销当前会话。

“认证环境配置”捕获已应用的网关、接口、账户选择和规则。先保存或放弃设置草稿，再保存环境；只有点击选择才切换，不创建第二个认证引擎。系统服务的目标变更仍由引擎校验管理员权限。环境快照不包含账户密码，删除环境不删除账户。

图形客户端运行期间，通过 [notify-rust](https://docs.rs/notify-rust/4.17.0/notify_rust/) 在当前用户会话发送原生通知。凭据错误或凭据存储不可用持续约 10 秒才通知；同一故障去重，通知之间至少间隔 15 分钟。通知只包含静态提示，不复制账户、地址、错误原文或密码。Windows 使用 BitNet 自身 AUMID，macOS 使用自身 bundle ID；系统拒绝或没有桌面通知服务时保留界面错误提示，不自动更改系统通知设置。GUI 未运行时不会产生桌面通知。

更新检查在 GUI 启动约 30 秒后独立运行，成功后约 24 小时再查、失败后约 1 小时再查；认证与本地状态查询不等待它。服务更新始终提示并等待主动授权；Linux/macOS 的系统安装包也只提示。Windows 个人安装只有在用户明确开启自动安装且未安装系统服务时，才可启动独立的个人更新器；“更新器已启动”不等于安装已经成功。

“恢复上一已验证版本”需要本机保留可用的上一版验签缓存，并且 API/schema 兼容。运行前会再次验证；没有缓存时明确报不可用，不表示首次安装就已有旧版，也不承诺自动回滚。服务回滚仍逐次请求管理员授权。

注销、强制重新认证、删除账户/规则、停止引擎及系统维护都有确认流程。手动注销会持续暂停自动认证，直到明确恢复；暂停意图先落盘，再执行注销。密码错误会暂停对应账户的自动重试，替换密码后恢复资格。

维护执行期间，GUI 可继续读取状态，但不会重新调用 `ensure_running` 启动引擎。服务暂不可用时显示错误，并保留明确的维护入口。

后台失联时保留最后成功快照，同时明确标记它已过期，服务状态显示“当前未知，上次…”。旧快照不会禁用重新启动服务的入口。定时状态读取不会启动引擎；用户明确选择重新连接时，才让 SDK 判断应连接系统服务还是恢复个人引擎。

## 构建及非 UI 验证

```text
cargo check -p bitnet-gui
cargo test -p bitnet-gui
cargo build -p bitnet-runtime --bin bitengine -p bitnet-cli --bin bitctl
python tests/e2e.py
```

`tests/e2e.py` 仅使用 Python 标准库，在项目 `.local/e2e/<独立运行目录>` 创建数据，同时设置 `BITNET_DATA_DIR` 与 `BITNET_SIMULATE_ONLY=1`，只启动 `--simulate` 引擎。正常操作经过真实 `bitctl` 子进程；仅过期 revision 案例按公开 IPC 帧格式提交不含密码的设置，并核对精确端点及引擎进程身份。每个子进程和整次测试都有超时；清理仅涉及本次启动、且已核对可执行路径的进程，不按名称批量终止。

模拟模式的账户只保存在内存；设置、暂停和账户错误阻止标记会落盘。模拟重启后出现默认 `demo` 账户属于预期，不能据此宣称真实凭据持久化已验证。真实 Windows 凭据存储由平台层的 DPAPI 测试覆盖。

端到端测试保留私有报告、脱敏日志和数据库；检查 CLI 输出、日志及持久数据没有合成密码。报告不证明真实校园认证、Windows 服务安装、签名发布、系统提权、托盘交互、macOS/Linux 实机表现或长期稳定性已通过验证。

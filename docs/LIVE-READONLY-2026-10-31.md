# 真实校园网只读验证（2026-10-31）

本轮经用户明确授权，在北京时间 15:16–15:35 观察当前已登录会话。结论限于本机 Windows、当前网络路径与当前在线响应。没有登录、注销、断网、改路由/DNS、读写账户库、修改启动项或安装服务；没有启动 BitNet 引擎或 GUI。

## 方法与结果

先从固定默认网关的 `/cgi-bin/rad_user_info` 收集一次有界 JSONP，再用 [手动只读验证工具](../tests/read_only_probe/README.md) 在 loopback 回放原始 JSON，调用正式 `GatewayClient::status`。仅替换 callback 名称，JSON 内容不变。随后由同一工具枚举原生网卡、选择实际来源接口，显式执行一次真实 `status`；它没有重试、认证、challenge 或发现流程。

| 原始字段 | 产品字段与单位 | 验证结果 |
| --- | --- | --- |
| `error` | 认证状态 | 当前 `ok` 正确解析为在线 |
| `user_name` | 当前网关账号 | 回放逐字符匹配；真实绑定查询与参考查询相同 |
| `online_ip` | 网关观测的认证 IP | 回放与真实查询匹配；与本机来源地址不同，符合路由器下游路径 |
| `sum_bytes` | `bytes_used`，字节 | 无缩放精确匹配；GUI 按 1024³ 显示 GiB |
| `sum_seconds` | `online_seconds`，秒 | 无缩放精确匹配；是网关累计值，不能视作本次连续会话 |
| `user_balance` | `balance`，网关余额原值 | 数值匹配，显示保留两位，不除以 100 |

六项字段比对全部通过。原始响应共 23 个字段，产品使用上述 6 个；其余兼容字段没有被解释成产品已实现的数据项。账号、完整 IP、MAC、姓名和实际用量不写入本公开报告。

Windows 原生网卡选择与独立的系统路由查询逐项一致：接口索引、来源 IPv4、网关和启用状态匹配。本机经 Hyper-V 以太网上联及路由器访问网关；没有活动 Wi-Fi，因而本轮不证明 SSID 获取或无线漫游正确。

按产品既有判据作独立只读健康参考检查：两个默认 HTTP 目标分别返回期望的 200/正文及 204，互联网判据为正常；BIT 域名解析成功。IPv6 探测未获得可用目标地址，结果为未知，不能推断校网不支持 IPv6。没有借此宣称整个引擎健康调度或故障恢复已验收。

结束时再次只读查询，确认仍在线、账号与网关 IP 相同、`add_time` 未变，流量和时长自然递增；测试前后系统网卡快照与目标路由相同。

## 官方门户交叉核对与修正

只读取门户 HTML 及静态脚本，不执行页面脚本、不导入浏览器 cookies。现场门户脚本的 `Info` 显示逻辑同样取 `sum_bytes`、`sum_seconds` 和 `user_balance`：流量除以 1024 的幂，时长按秒拆分，余额保留两位。门户把 1024³ 标作 GB 并截断两位；本应用使用 GiB 并四舍五入，两者末位可差 0.01，属于显示方法差异。

脚本没有给出统计周期或复位规则，不能把这些值擅自称为“本月”或“本次连接”。本轮将 GUI 两处文案改为“网关统计流量”“网关累计在线时长”“校方网关统计”，补充周期说明；本地观测在线时长仍是另一项统计。

## 证据与边界

公开的脱敏检查摘要见 [validation-2026-10-31.json](validation-2026-10-31.json)。原始响应、完整 Rust 比对报告和系统参考快照仅在项目忽略目录 `.local/live-readonly/20261031-151620/`，设置了私有 ACL，不进入源码归档或发行包。

- 校园网请求：3 次状态 GET、5 次门户/静态文件 GET；没有请求 `/cgi-bin/srun_portal` 或 `get_challenge`。另外只有 2 次默认外网健康 GET、DNS/IPv6 只读探测及 loopback 回放。
- 工具的 4 项合成/loopback 测试及严格 Clippy 通过；GUI 13 项现有回归测试、严格 Clippy、格式检查通过。单元测试没有新增真实网络操作。
- 未验证离线响应、主动登录/注销、密码拒绝、被其他账号占用、睡眠/故障恢复、自动重连、其他校园接入路径或平台。不会为补验这些分支主动中断当前会话。
- 本轮证明当前在线接口、正式传输与解析兼容；不能替代校方计费核验、全平台验收或长期稳定性验收。

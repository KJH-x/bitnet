# 计划：三平台加密诊断包

决策记录：2026-11-11。状态：**计划中，暂不实施**。本条目不改变当前诊断命令、客户端、服务或安装包。

| 事项 | 已定决策 |
| --- | --- |
| 数据 | 手动触发时默认保留诊断所需技术信息的原值，包括 IP、校园账号名、网卡、路由、进程路径等。字段须显式列入报告模型；不采集密码、令牌、Cookie、SRUN 认证材料或代理控制器密钥，不打包账户库、原始认证响应或整份配置文件。 |
| 预览 | 软件内只显示结论、异常、检查缺失及导出进度等摘要。完整 HTML 拓扑由维护者解密后查看。 |
| 导出 | 压缩后用内嵌诊断公钥流式加密，拟采用 age/X25519，输出 `.tar.gz.age`；只保存本地，由用户手动发送。缺少公钥或加密失败即中止，无明文回退。 |
| 解密 | 仅持有对应私钥的项目维护者解密。诊断密钥独立于 Minisign 更新签名密钥，客户端与发行物只含公钥；旧私钥由维护者妥善保管，以读取历史包。 |
| 代理分析 | 跳过需要控制器密钥的 API，并标明缺失原因；不从配置、命令行或环境提取密钥。 |
| 平台 | 同一轮支持 Windows、Linux、macOS；补 macOS 采集后端。权限不足和平台能力缺失如实记录，无自动提权。 |

实施时，以本地 `netdiag-rust-20260920` 为分析引擎来源，记录复用版本与许可来源；分离采集、分析和渲染，保留拓扑能力。既有分析器的明文 HTML 输出、终端原文、自动打开、视觉模糊及认证代理 API 路径不能直接用于该功能。校园会话状态复用 BitNet 已验证的只读模型；诊断不调用登录、注销或修改网络。GUI 与 CLI 共用按需、普通用户权限的诊断进程，限制采集时长、并发与输出，支持取消及可说明的部分结果；认证引擎不等待诊断。

归档包含版本化清单、完整 HTML 拓扑、结构化分析结果、BitNet 状态和有限的选定日志。报告内容在内存中送入压缩及加密流程，磁盘只写入密文，完成后才发布最终文件；预览、日志、错误与文件名不泄露完整报告。维护端离线解包工具先验证密文及归档成员、路径和体积，解包后不自动打开 HTML。

计划验收：合成数据验证正确私钥还原、错误私钥及篡改/截断失败；检查成功、失败和取消路径无明文残留；确认跳过需要密钥的 API，确认无认证或网络变更。三平台分别验证权限、进程回收、资源上限及打包；没有实机证据的平台标为待验。

现场快照确认：共享系统后台处于 idle，自动认证关闭，未手选网卡，`active_binding` 为空。Windows 给校园网关选择的是接口 33 Mihomo 的默认路由；BitNet 自动选卡会排除该隧道，然后返回没有绑定。因此「立即检测」实际没有查网关，认证数据为空且信任按钮不可用。当前候选是已连接、IPv4 与网关均为 10/8 的以太网 18，其次是使用 192.168/16 的 WLAN 10。可先在偏好页放弃旧设置草稿，在网络页明确选择以太网 18，在保持自动认证关闭的前提下只读检查，观察是否有绑定及网关返回。应用选卡不改 Windows 路由；这条路径能否到达网关待实测。

## 首次启用自动认证与网络信任

- 输入并保存校园账户后，后台自动做只读探测，按网卡优先级尝试确定默认认证出口。能唯一锁定符合条件的 10/8 候选时记录建议结果；不能锁定时记录原因，先完成账户保存，暂不弹出选卡或触发登录。
- 用户主动启用「自动保持登录」后，若有唯一候选且仍有效，直接进入网络信任确认；否则打开网卡选择对话框，按前述顺序推荐候选。确认框显示网卡和当前网络，简要提示「开启自动保持登录前，请确认这是你要信任的校园网」。只有当前网络信任保存成功才完成启用。已经保存且仍匹配的信任可直接复用。取消、确认失败或出口不可用时保留账户，启用流程可重试。
- 按现场提供的网络分类，WLAN `BIT-mobile` 由系统 Wi-Fi 认证，BitNet 保持静默，不做门户登录或登出。WLAN `BIT-web` 按用户设置和当前信任决定是否自动登录。有线先用少量不含凭据的定向探测区分校园门户与其他网络，10/8 地址只用于推荐。已识别的校园门户才进入确认流程，其他网络保持静默。
- 区分已保存的认证配置和当前会话。支持按网卡及其所连网络分别记忆信任和自动登录意图，避免同一网卡换到陌生网络时沿用许可，或把另一出口的断线、重试与暂停状态串进当前出口。进一步核对多个校园出口共存时的活动出口选择与会话归属；避免让多个网卡上的自动登录争抢同一会话。首页不常驻信任说明，已知校园门户确需用户确认时才提供短提示及入口。
- 源码中确认按钮目前只提交 `TrustNetwork { trusted: true }`。引擎处理时会重新检测，再按当时的网络指纹保存。首次流程需校验用户看到的网络与最终保存的指纹一致，换网后要求重新确认；并覆盖账户刚保存导致的设置版本变动、取消及重复提交。

## 网页注销后未自动重连

现场有两个序列：A 在线时登记 B，网页注销 A 后 B 未上线；B 在线时从网页注销，随后也未恢复。截图已显示以太网认证 IP 和「尚未认证」，且有 `login_failure`、`incompatible` 和重试记录，说明至少有一轮进入了登录流程，遇到被拒绝的 HTTP 重定向。现有通用错误无法区分是查询会话、发现门户参数、请求挑战、提交认证还是复核阶段收到重定向。保存第二个账户只登记凭据，当前自动登录账户还取决于当前账户设置及匹配规则；两段操作各自选中了哪个账户、登录由自动还是手动触发，需结合时间线核对。

2026-11-12 现场导出的 36 条系统后台事件按 ID 对齐如下（北京时间，日志时间为后台观察时间）：

| 时间 | 后台事件 | 观察结果 |
| --- | --- | --- |
| 14:09:48 | #3 | 记录一次账户保存。此后八次失败均使用该记录的同一个内部账户 ID，导出中没有第二个账户保存事件。网页会话记录没有用户名，无法仅凭导出将这个内部 ID 对应到用户描述中的 A 或 B。 |
| 16:12:04–16:13:27 | #12–23 | 16:12:04 观察到离线；四次登录调用都收到重定向拒绝。从 16:13:04 起有定时失败及退避记录。16:13:27 只读复查观察到重新在线。 |
| 16:14:27–16:15:50 | #24–36 | 16:14:27 再次观察到离线；同一账户四次定时登录调用失败。16:15:50 只读复查观察到重新在线。 |

两轮均在同一个网络指纹及同一网络代次下。相邻的 `login_failure` 与 `error`（`retrying`）来自定时任务路径，证明自动任务确实运行。两条恢复记录均没有账户，导出无 `login_success`，只能证明后来观察到在线。各次登录调用耗时 3–6 ms，可排除提交已返回成功后等待三次间隔、在最后一次复查才收到重定向的路径。仍需区分登录前复查、门户参数发现、挑战和登录提交。

## 通知与侧栏状态

- 保存、检测等一次性结果条幅超时自动收起，仍可手动关闭。连接丢失、自动认证待确认等持续状态由实际状态驱动；后台恢复后立即更新侧栏，旧连接警告随之清除。需处理的操作失败在对应操作处保留可重试入口，避免条幅消失后丢掉处理线索。
- 参考 Clash Verge 截图的侧栏底部布局，在版本号附近常驻简短文字，显示「已连接系统后台」「已连接独立引擎」「正在连接」「未连接」等。状态来源为实际后台连接及当前范围，与校园网认证状态分别显示。
- 「实时网速」在设置内显式启用，默认关闭并且不采样。开启后仅对当前生效的主网卡每 1 秒读取一次接口累计收发字节，用差值计算实际上传和下载速率，侧栏只显示文字和数值。没有主网卡时显示「—」；切卡、断开或计数器重置后重新取基线，避免速率尖峰。网卡总收发包含其他应用与局域网流量，网关账户用量单独保留原含义。

## 滚动手感

现场报告滚动「卡手」。源码确认页面使用 Iced 默认滚动组件，无 BitNet 自定义倍速。当前依赖把 Windows 标准鼠标滚轮的一格换算成 1 个滚轮单位，Iced 对该类事件立即移动约 60 个逻辑像素；像素型滚动事件另行处理，不应套用同一倍速。网卡页逐个展开高卡片，固定步长会让跨条目的滚轮操作次数增加。软件渲染、高分屏的绘制成本、长列表布局及定时状态/托盘消息也可能影响连续性，尚无故障机帧耗时证据，不能直接认定掉帧。

先用同页滚轮与拖动滚动条滑块作对照：拖动流畅而滚轮短促，优先处理步长和卡片密度；两者都停顿，再测窗口尺寸/缩放、滚动帧间隔、布局时间和定时消息的相关性。如果仅在输入框或内层区域上方异常，另查嵌套滚动和事件交接。当前只登记和读源码，不调整全局滚轮速度，不换渲染后端。

用户补充：每格距离短，连续拨动表现为一格一跳，希望连续动画和快速拨动时累加加速。当前锁定的 `iced_widget 0.14.2` 对鼠标滚轮直接更新偏移，没有逐帧补间或速度累计。Iced 提供按帧回调和程序控制偏移的接口，可以在现有框架内做。原型调查优先拦截页面的刻度滚轮输入并累加有上限的目标位移，短时逐帧靠近目标，停稳即停止额外重绘。反向输入即时响应，拖动滚动条和触控板像素事件保持直接；先比较实际帧间隔和静止开销，再决定是否加入更长的惯性尾段。需要验证嵌套滚动区及边界事件交接。
